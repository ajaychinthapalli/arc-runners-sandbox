## 🟠 Fix Before Upgrade

### 2. Runner image pinned to `latest` — unacceptable for production

`arc-runner-set` uses `ghcr.io/actions/actions-runner:latest`. This is a floating tag — the running version is unknown, rollback is impossible, and the image may silently change between pod restarts. The current latest `actions/runner` release is **v2.338.0**.

Pin the runner image in your scale set `values.yaml`:

```yaml
template:
  spec:
    containers:
      - name: runner
        image: ghcr.io/actions/actions-runner:2.338.0
```

### 3. Runner image is outdated relative to latest runner release

The `latest` tag almost certainly resolves to a runner older than v2.338.0. The 0.15.0 chart bundles runner v2.337.0 internally; anything older carries known bugs fixed in later releases.

### 4. `--default-max-concurrent-reconciles` flag removed in 0.15.0

If this flag is present in your controller `values.yaml` under `args`, the controller pod will fail to start after upgrade. It has been replaced by per-controller settings.

Check your current args:

```bash
kubectl get deployment arc-gha-rs-controller -n arc-systems \
  -o jsonpath='{.spec.template.spec.containers[0].args}'
```

Remove `--default-max-concurrent-reconciles` from your `values.yaml` before upgrading.

## 🟡 Warnings

### 5. Significant behavioral changes in 0.15.0

| Area | Change |
|---|---|
| Reconciliation model | Resources upgraded in-place (1-1 mapping between AutoscalingRunnerSet and EphemeralRunnerSet). The `actions.github.com/change-hash` annotation is removed; tracking now uses `metadata.generation`. |
| Status fields removed | AutoscalingRunnerSet printer columns `pendingRunners`, `runningRunners`, `finishedRunners`, `deletingRunners` are removed — replaced by metrics. Dashboards or scripts reading these fields will break. |
| Listener drift detection | Listener pod is now replaced by comparing the pod spec directly (not a hash). Expect a one-time listener pod restart on first upgrade. |
| Outdated runner lifecycle | Runners in an `Outdated` phase now cause the scale set to switch off (drain) rather than rebuild immediately. This changes draining behaviour during rolling upgrades. |
| Metadata validation | Chart now rejects integer values in labels/annotations at render time. `helm upgrade` will error if any are present. |
| Scale-set re-registration | Scale sets that disappear from the Actions service are now automatically re-registered — no manual intervention needed. |
| Secret deletion handling | Deleting the `githubConfigSecret` now cleanly releases the AutoscalingRunnerSet finalizer. |

### 6. Validate in staging first

The 0.15.0 release is a large internal reconciliation refactor. Run it in a non-production environment before rolling to production.
